# บันทึกการคุย: Excel schema draft และการออกแบบฐานข้อมูลแบบ iterative

วันที่จัดทำ: 2026-09-14

ประเภท: บันทึกจากคำยืนยันและแผนการทำงานที่เจ้าของโครงการระบุในบทสนทนาปัจจุบัน

## เป้าหมายและสถานะก่อนเริ่ม

หลังจากเลือก PostgreSQL เป็นฐานข้อมูลหลัก เจ้าของโครงการแจ้งว่าจะนำไฟล์ Excel ที่ทำ database คร่าว ๆ มาให้ศึกษา ไฟล์ดังกล่าวอาจยังไม่ครบทุกตาราง และยังไม่ใช่ schema ที่ปิดสมบูรณ์

ขณะจัดทำบันทึกนี้ยังไม่พบไฟล์ Excel ใน repository จึงยังไม่มีการวิเคราะห์ชื่อ Sheet ตาราง คอลัมน์ หรือความสัมพันธ์จากไฟล์จริง

## คำยืนยันของเจ้าของโครงการ

- Excel จะใช้เป็นร่างฐานข้อมูลตั้งต้นสำหรับการพูดคุยและวิเคราะห์
- ไม่จำเป็นต้องมีตารางครบทุกตารางตั้งแต่เริ่มต้น
- ระหว่างพัฒนาจะมีฟังก์ชันและโมดูลเพิ่มเติม ซึ่งอาจทำให้ต้องเพิ่มตารางใหม่

## ผลต่อแนวทางออกแบบ

- PostgreSQL ยังคงเป็นฐานข้อมูลหลักตาม [ADR-0002](../../decisions/ADR-0002-postgresql-as-primary-database.md)
- การมีตารางเพิ่มภายหลังเป็นแนวทาง iterative ที่ต้องควบคุมด้วย migration และเอกสาร ไม่ใช่เหตุผลให้เดาตารางที่ยังไม่มี requirement
- ตารางที่วิเคราะห์จาก Excel ต้องแยกเป็น confirmed, draft/proposed และ missing ก่อนนำไปออกแบบ physical schema
- ต้องรักษา Global Master และขอบเขต Jar Test ที่ได้รับการยืนยันแล้วเป็นแกนร่วม โดยไม่ล็อกส่วนที่ยังไม่ทราบรายละเอียด

## สิ่งที่ทำจริง

- ปรับ [PROJECT-STATE.md](../../../PROJECT-STATE.md) ให้ระบุ schema draft และการพัฒนาแบบ iterative
- เพิ่มบันทึกนี้ใน [Project Memory](../README.md) และ [Documentation Index](../../README.md)
- ยังไม่เพิ่มหรือแก้ physical database schema เพราะยังไม่ได้รับไฟล์ Excel และยังไม่มี requirement ของฟังก์ชันใหม่

## สิ่งที่ยังขาด

- ไฟล์ Excel สำหรับวิเคราะห์
- ขอบเขตว่าตารางใดเป็น Global Master และตารางใดเป็นข้อมูลระดับ Organization, Business Unit หรือ Site
- ความสัมพันธ์การใช้ `raw_unit` ระหว่างหลาย Site
- tenant isolation, naming convention และ migration strategy

## ขั้นถัดไป

รับไฟล์ Excel แล้วตรวจทุก Sheet, ตาราง, คอลัมน์, key และความสัมพันธ์ โดยเทียบกับ `CONTEXT.md`, Target Domain Model, ADR และ Legacy Jar Test baseline ก่อนเสนอการปรับ schema
