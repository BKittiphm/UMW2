# บันทึกการคุย: โครงสร้างประเภทแหล่งน้ำและ Jar Test

วันที่จัดทำ: 2026-09-09

ประเภท: สรุปจากคำอธิบายและภาพโครงสร้างที่ผู้ใช้ส่งในบทสนทนาปัจจุบัน ภาพต้นทางอยู่ในไฟล์ชั่วคราวของเครื่องและไม่ได้เพิ่มใน repository

## ข้อเท็จจริงที่ผู้ใช้ยืนยัน

1. ภายในองค์กรมีน้ำหรือแหล่งน้ำหลายประเภท
2. `wq_source` เป็นตัวเลือกประเภท ไม่ใช่รายการแหล่งน้ำจริง
3. เมื่อเลือกประเภท ระบบแสดงหลายรายการจากตารางของประเภทนั้น
4. ตารางประเภทแยกกันจริงตามชื่อ ได้แก่ `raw_unit`, `potable_unit`, `potable_tranfer_unit`, `sedimentation_unit` และ `filtration_unit`
5. แต่ละรายการในตารางประเภทมี `wq_source_id` เชื่อมกลับไปยัง `wq_source`
6. Jar Test ใช้เฉพาะน้ำดิบ ฟิลด์ `water_source` ใน Jar Test จึงเชื่อมกับรายการใน `raw_unit`
7. โครงสร้างระดับบนยังเป็น Organization → Business Unit → Site และ Site มีบริบทของ `wq_source`

ตัวอย่างที่ผู้ใช้ยืนยันว่าตรงกับความหมาย:

```text
Site: Head Office
├─ wq_source: น้ำดิบ
│  ├─ raw_unit: น้ำดิบ LPTHEP
│  └─ raw_unit: น้ำดิบรายการอื่น
├─ wq_source: น้ำประปา
│  ├─ potable_unit: จุดน้ำประปา 1
│  └─ potable_unit: จุดน้ำประปา 2
└─ wq_source: น้ำหลังกรอง
   └─ filtration_unit: จุดกรองต่าง ๆ
```

## ความเข้าใจที่ถูกปรับ

ก่อนหน้านี้เอกสาร target เคยตีความ Water Source เป็นรายการจริงใน Global Master และเชื่อมกับ Site แบบ many-to-many การตีความนี้ไม่ถูกใช้ต่อสำหรับ Jar Test เพราะผู้ใช้ยืนยันว่า `wq_source` เป็นประเภท ส่วนรายการจริงอยู่ในตารางแยก และ Jar Test เลือกจาก `raw_unit`

คำยืนยันก่อนหน้าว่าแหล่งน้ำหนึ่งแหล่งสามารถใช้ร่วมกันหลาย Site ยังมีผลในระดับความต้องการ แต่ยังไม่ทราบว่าจะผูก `raw_unit` รายการเดียวกับหลาย Site อย่างไร จึงต้องเก็บเป็น Open Decision

## สิ่งที่ยังไม่ยืนยัน

- `raw_unit` รายการเดียวแชร์หลาย Site ผ่านตารางกลางหรือโครงสร้างอื่น
- `wq_source` เป็นประเภทกลางร่วมกันหรือสร้างรายการประเภทแยกต่อ Site
- ชื่อ `potable_tranfer_unit` ในภาพเป็นชื่อ schema ที่ต้องคงไว้หรือเป็นคำสะกดที่จะแก้ภายหลัง
- ความสัมพันธ์ exact cardinality และ foreign keys นอกเหนือจาก `wq_source_id` ที่ผู้ใช้ยืนยัน
- รายละเอียดคอลัมน์ของตารางประเภทน้ำ
- Global Master แบ่งตาม Organization หรือแชร์ข้าม Organization

## จุดเริ่มคุยครั้งถัดไป

ถามวิธีแชร์ `raw_unit` รายการเดียวระหว่างหลาย Site แล้วจึงคุย ownership/cardinality ของ `wq_source` ต่อ ห้ามเลือก schema แทนผู้ใช้ก่อนทราบสองข้อนี้
