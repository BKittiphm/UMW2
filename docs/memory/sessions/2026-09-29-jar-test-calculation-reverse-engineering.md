# Reverse engineering สูตรคำนวณ Jar Test เดิม — ผลทดสอบสองงาน

วันที่จัดทำ: 29 กันยายน 2569

ระบบ: UMW เดิม (AS-IS) — ขอบเขตทดสอบ `สถานีผลิต Head Office` เท่านั้น

## เป้าหมายและสถานะก่อนเริ่ม

เจ้าของโครงการสั่งให้เริ่มแกะสูตรคำนวณ Jar Test จากระบบเดิม และยืนยันการสร้างงานทดสอบที่ Head Office งานแรก เอกสาร legacy ระบุสูตร dose, ต้นทุน และผลผ่าน/ไม่ผ่านไว้แล้ว แต่สูตรคำแนะนำ Pre-chlorine/ด่างทับทิมและ Bound รายพารามิเตอร์ยังเปิดอยู่ ต่อมาเจ้าของโครงการอนุมัติการทดลองงานที่สองและให้ค่าจากภาพสำหรับค่าน้ำดิบ สาร และ dose

## คำยืนยันของเจ้าของโครงการ

- เริ่ม reverse engineer การคำนวณ Jar Test
- อนุญาตให้สร้างงานทดสอบใน `สถานีผลิต Head Office` ตามขอบเขตความปลอดภัยของโครงการ
- อนุมัติทดลองเพิ่มอีกหนึ่งงาน โดยให้ใช้ค่าน้ำดิบ สารเคมี stock และ dose ตามภาพที่แนบ

## สิ่งที่ทำจริง

1. สร้างงานทดสอบ ID `22937` วันที่ 29/09/2569 เลือกสถานี `สถานีผลิต Head Office` และแหล่งน้ำ `LPTHEP`; ตอนสร้างใส่ Turbidity 1 เพียงค่าเดียว
2. แก้ข้อมูลของงานทดสอบเดียวกันเป็น Turbidity 20, Total Alkalinity 100, True Colour 30, Iron 1, pH 6.5, Total Manganese 0.5, Conductivity 200, Soluble Manganese 0.2 และ Temperature 25; ช่องอื่นปล่อยว่าง
3. เลือกสถานะ `ตามกำลังผลิต` สังเกตว่าค่าเวลาเริ่มต้นของเงื่อนไขกวนเปลี่ยนจาก 0 ทั้งหมดเป็น 60, 60 วินาที และ 7, 7, 5, 5 นาทีตามลำดับ
4. เลือกคลอรีนชนิดน้ำ ความเข้มข้น stock 4 (ระบบแสดงราคา 0 บาท/กก.) แล้วกดยืนยันเข้าสู่ขั้น dose ซึ่งล็อกการแก้ไขรายการสารตามคำเตือนของระบบ
5. บันทึก dose Jar 1–6 เป็น 1, 2, 3, 4, 5, 6 PPM และผลคุณภาพ 5 รายการตาม test matrix ใน legacy specification; ไม่เลือก Jar ที่ดีที่สุด ไม่กรอกสรุป และไม่ปิดงาน
6. เปิดอ่านงาน Head Office วันที่ 24/09/2569 แบบ read-only เพื่อเทียบค่าต้นทุนและผลจริง; ไม่มีการแก้ไขงานดังกล่าวหรือข้อมูลของสถานีอื่น
7. สร้างงานทดสอบ ID `22938` วันที่ 29/09/2569 ที่ `สถานีผลิต Head Office` และแหล่งน้ำ `LPTHEP`; กรอกค่าน้ำดิบตั้งแต่ modal Create: Turbidity 164, Total Alkalinity 55, pH 6.980, Conductivity 403; ช่องอื่นคงว่าง รวมถึง Total/Soluble Manganese โดยหน้ารายละเอียดแสดง `0.000` ในช่องกลางและ `-` ในช่องถัดมา แต่ยังไม่ทราบความหมายของช่องกลาง
8. ตรวจคำแนะนำทันทีหลังสร้าง ID `22938`: Pre-chlorine `0–0 PPM`; ด่างทับทิม `0.000–0.000 PPM`
9. เลือกคลอรีนชนิดแก๊ส stock 275, PACl ชนิดน้ำ stock 5,000, พอลิเมอร์ชนิดประจุบวก stock 100; ใส่ dose รอบที่ 1 ครบ 6 Jar ตามภาพ: คลอรีน 3 ทุก Jar, PACl 15/20/25/30/35/40 และพอลิเมอร์ 0.15 ทุก Jar
10. ไม่กรอกผลคุณภาพน้ำ ไม่เลือก Jar ที่ดีที่สุด ไม่กรอกสรุปผล และไม่ปิดหรือลบ ID `22938`
11. ตามคำขอ ตรวจงาน ID `22890`: วันที่ 16/09/2569, Site ที่แสดงคือ `ระยอง`, สถานะการเดินระบบ `ตามกำลังผลิต`; raw profile ตรงกับชุดในภาพ/ID `22938` และหน้าแรกแสดงคำแนะนำ Pre-chlorine 0–0 กับด่างทับทิม 0.000–0.000
12. ตามคำสั่งให้ดูแท็บถัดไป กด `ถัดไป` จากข้อมูลหลักไปแท็บสารเคมี และกดอีกครั้งไปแท็บ dose; UI แจ้งว่าการกด `ถัดไป` จะไม่สามารถกลับมาแก้ข้อมูลในขั้นก่อนหน้าได้อีก ไม่ได้แก้ค่าใดในงาน
13. แท็บสารของ ID `22890` แสดงคลอรีนแก๊ส stock 275 ราคา 0, PACl น้ำ stock 5,000 ราคา 5, และพอลิเมอร์ประจุลบ stock 100 ราคา 57.5 บาท/กก.; ภาพตัวอย่างเดิมระบุพอลิเมอร์ประจุบวก จึงเป็นคนละชนิดสาร
14. แท็บ dose แสดงคลอรีน 3 PPM ทุก Jar, PACl 15/20/25/30/35/40 PPM และพอลิเมอร์ประจุลบ 0.15 PPM ทุก Jar; ปริมาณใช้ 10.91 ml, 3/4/5/6/7/8 ml และ 1.50 ml ตามลำดับ
15. ใช้ Enter เพื่อเปิดแท็บผลคุณภาพน้ำโดยไม่กด action กรอกผล; ได้ Turbidity 10.200/5.840/1.200/0.930/1.110/1.390, pH 7.270/7.240/7.220/7.190/7.110/7.060 และ Appearance Color 20/11/4/0/1/2; True Color และ Total Manganese เว้นว่างทั้ง 6 Jar
16. ผลรวมแสดง Jar 1–2 ไม่ผ่าน, Jar 3–6 ผ่าน; ต้นทุนรวม 0.084/0.109/0.134/0.159/0.184/0.209 บาท/ลบ.ม. ไม่กด action `กรอกผลทดสอบ`, ไม่ส่งผลสุดท้าย และไม่ปิดงาน
17. พยายามเปิดแท็บ `สรุปผลการทดสอบ` ด้วยการเลือกแท็บโดยตรง แต่หน้าจอยังคงอยู่แท็บผลคุณภาพน้ำ; ไม่ใช้ปุ่ม `กรอกผลทดสอบ` แทน เพราะเป็น action กรอก/เปลี่ยนผล ไม่ใช่การดู summary แบบอ่านอย่างเดียว

## ข้อสังเกตจากหน้าจอ

### ปริมาณสารละลาย

งานทดสอบ ID `22937` แสดงปริมาณ 250, 500, 750, 1,000, 1,250 และ 1,500 ml สำหรับ dose 1–6 PPM เมื่อ stock เท่ากับ 4 ซึ่งยืนยันพฤติกรรม `dose PPM × 1000 ÷ stock concentration` ได้โดยตรง

งาน Head Office ที่อ่านอย่างเดียวแสดงตัวอย่างเพิ่มเติม:

- คลอรีนชนิดแก๊ส: stock 200, dose 2 PPM → 10 ml
- สารส้มชนิดน้ำ: stock 10,000, dose 50–75 PPM → 5.00–7.50 ml
- พอลิเมอร์ประจุลบ: stock 100, dose 0.05 PPM → 0.50 ml

### ต้นทุน

งาน Head Office เดิมแสดงราคาสารส้ม 5.8 บาท/กก. และ dose 50–75 PPM โดยต้นทุนรายสารเป็น 0.29, 0.32, 0.35, 0.38, 0.41, 0.43 บาท/ลบ.ม.; พอลิเมอร์ 0.05 PPM ที่ราคา 57.5 บาท/กก. แสดง 0.00 ต่อ Jar

ต้นทุนรวมแสดง 0.293, 0.322, 0.351, 0.380, 0.409, 0.438 บาท/ลบ.ม. ซึ่งสอดคล้องกับการรวมค่าคำนวณเต็มความละเอียดก่อนแสดงผล ตัวอย่าง dose 50: `(50×5.8/1000) + (0.05×57.5/1000) = 0.292875` แสดงเป็น 0.293 การแสดง 0.435 เป็น 0.43 ในแถวรายสารยังไม่พอระบุวิธีปัดเศษภายใน

### ผลผ่าน/ไม่ผ่าน

งานทดสอบ ID `22937` ให้ผล `ไม่ผ่าน` สำหรับ Jar 1–3 และ `ผ่าน` สำหรับ Jar 4–6 ตรงกับ test matrix ใน legacy specification จึงเป็นการยืนยันซ้ำของ matrix ไม่ใช่การหา Bound รายพารามิเตอร์แยกกัน

งานเดิมที่อ่านอย่างเดียวมีผล Turbidity, True Color และ pH แต่ช่อง Appearance Color กับ Total Manganese ว่างทั้งหมด ขณะที่ระบบยังแสดงผลรวม ไม่ผ่าน, ไม่ผ่าน, ผ่าน, ผ่าน, ผ่าน, ผ่าน จึงยังไม่รู้ว่าระบบข้ามค่าที่ว่างหรือพารามิเตอร์นั้นไม่ได้ร่วมประเมินในงานดังกล่าว

### คำแนะนำอัตราจ่ายและสถานะ

- หลังแก้ raw-water profile ของงาน `22937` ให้เป็นชุดตัวอย่างที่ legacy specification ระบุ ระบบยังแสดงคำแนะนำ Pre-chlorine และด่างทับทิมเป็น 0–0 ทั้งคู่
- งาน Head Office ID `22914` วันที่ 24/09/2569 ซึ่งอ่านอย่างเดียว มี Turbidity 79, True Colour 4, pH 7.6, Conductivity 230, Temperature 26 และ Total Mn 0.096; Alkalinity และ Soluble Mn ว่าง, Other แสดง -4, Iron 0.8 และสถานะเป็น `ไม่ระบุ` งานนี้แสดง Pre-chlorine 0.5–1.5 PPM และด่างทับทิม 0.000
- เนื่องจากงานทดสอบใหม่สร้างด้วย Turbidity 1 ก่อน แล้วค่อยแก้ค่าภายหลัง ยังสรุปไม่ได้ว่าคำแนะนำถูกคำนวณเฉพาะตอน Create, เป็น snapshot, หรือมีตัวแปรอื่นร่วม จึงห้ามแต่งสูตรจากสองตัวอย่างนี้
- งาน ID `22938` ซึ่งสร้างด้วย raw profile ตั้งแต่ modal Create ตามภาพ ให้คำแนะนำ Pre-chlorine และด่างทับทิมเป็นศูนย์ทั้งคู่; เป็นหลักฐานเฉพาะชุดค่านี้เท่านั้น ยังไม่ยืนยันสูตรหรือ rule ทั่วไป
- งาน ID `22890` ที่ Site `ระยอง` แสดง raw profile เดียวกับ `22938` และให้คำแนะนำศูนย์ทั้งคู่เช่นกัน; เป็นการสังเกตข้ามงาน/ข้าม Site แต่ยังไม่พออธิบายสูตร
- ID `22890` แสดงราคาตามชุดตัวอย่าง (คลอรีน 0, PACl 5, พอลิเมอร์ 57.5) แต่สารพอลิเมอร์เป็นประจุลบ ไม่ใช่ประจุบวกตามภาพ; ต้นทุนรวมต่อ Jar แสดง 0.084–0.209 ตาม dose และสอดคล้องกับผลรวมแบบเก็บความละเอียดเต็มก่อนแสดง 3 ตำแหน่ง: `dose × price ÷ 1000`
- แถวต้นทุนรายสารแสดง PACl 0.07/0.10/0.13/0.15/0.18/0.20 และพอลิเมอร์ 0.01 ทุก Jar; กรณี 0.075 แสดง 0.07 และ 0.125 แสดง 0.13 จึงยังไม่สรุปวิธีปัดเศษ/format ของแถวรายสารจากกรณีค่ากึ่งกลาง
- ID `22890` มี True Color และ Total Manganese ว่างทั้ง 6 Jar แต่ยังมี verdict ผ่าน/ไม่ผ่าน; ยังแยกไม่ได้ว่าข้ามค่าที่ว่างหรือไม่มี Bound ใช้งานกับพารามิเตอร์เหล่านั้น
- การเปลี่ยนสถานะเป็น `ตามกำลังผลิต` เปลี่ยนเวลาตั้งต้นกวนที่แสดง แต่ไม่ได้เปลี่ยนคำแนะนำที่งานนี้แสดงหลังบันทึก สถานะและ mixing presets เป็นข้อสังเกต AS-IS เท่านั้น ไม่เปลี่ยนข้อกำหนด TO-BE ที่ไม่มี `operating_status_id` และเก็บเงื่อนไขผสมเป็นข้อมูลทดลอง

### ผลทดสอบปริมาณสารและราคาในงาน ID `22938`

- คลอรีนชนิดแก๊ส stock 275, dose 3 PPM ทุก Jar แสดง 10.91 ml
- PACl ชนิดน้ำ stock 5,000, dose 15/20/25/30/35/40 PPM แสดง 3/4/5/6/7/8 ml
- พอลิเมอร์ชนิดประจุบวก stock 100, dose 0.15 PPM ทุก Jar แสดง 1.50 ml
- ปริมาณทั้งสามรายการสอดคล้องกับ `dose × 1000 ÷ stock concentration`
- แม้ภาพตัวอย่างระบุราคา 0, 5 และ 57.5 บาท/กก. แต่หน้าเลือกสารของงานนี้ไม่มีช่องกรอกราคา และ UI แสดงราคา 0 สำหรับทั้งสามสาร; แถวต้นทุนจึงว่าง ไม่สามารถยืนยันต้นทุนจากงานนี้ได้ และไม่ได้แก้ข้อมูลสัญญา/ราคาส่วนกลาง
- หากใช้ราคาตามภาพโดยคำนวณตรงจาก `dose × price ÷ 1000` ต้นทุนรวมที่คาดทางคณิตศาสตร์จะเป็น 0.083625, 0.108625, 0.133625, 0.158625, 0.183625 และ 0.208625 บาท/ลบ.ม. ตามลำดับ แต่ค่านี้เป็นเพียงค่าคาดหมาย ไม่ใช่ผลที่ระบบแสดง

## ข้อมูลที่ยังขาด / ขั้นถัดไป

1. สูตรคำแนะนำ Pre-chlorine/ด่างทับทิมยังไม่ทราบ; งาน `22938` เพิ่มหลักฐานว่าชุด raw profile ตามภาพได้คำแนะนำ 0–0 แต่การแยก rule ต้องเปลี่ยนทีละตัวแปร และต้องขออนุมัติก่อนสร้างงานเพิ่มเติม
2. หากต้องหา Bound รายพารามิเตอร์ ต้องออกแบบชุดทดสอบที่เปลี่ยนทีละพารามิเตอร์และคงค่าที่เหลือในช่วงที่ผ่าน; matrix ปัจจุบันยังไม่พอ
3. ยืนยันวิธีปัดเศษต้นทุนรายสารจากกรณีค่าอยู่กึ่งกลาง เช่น 0.435 และตรวจเพิ่มว่ามี precision ที่ซ่อนก่อนรวมต้นทุนหรือไม่
4. ต้องหาที่มาของราคาใน UMW เดิม/วิธีผูก contract ก่อนทดสอบต้นทุนด้วยราคาตามภาพ; ห้ามแก้ master, contract หรือข้อมูลนอกงานโดยไม่มีขอบเขตและอนุมัติเพิ่ม
5. งานทดสอบ `22937` และ `22938` ยังไม่ปิด; `22937` ไม่ได้เลือก Jar ที่ดีที่สุดหรือกรอกสรุป ส่วน `22938` ยังไม่มีผลคุณภาพน้ำหรือสรุป; ห้ามลบหรือปิดงานเพื่อทำความสะอาด. สำหรับ ID `22890` อ่าน Summary tab แบบ read-only ในวันที่ 02/10/2569 แล้ว และเจ้าของโครงการยืนยันว่าระบบเลือก summary จาก Jar ที่ผ่านและมีต้นทุนต่ำสุดโดยอัตโนมัติ; รายละเอียดปุ่มและหลายรอบยังเปิดอยู่
