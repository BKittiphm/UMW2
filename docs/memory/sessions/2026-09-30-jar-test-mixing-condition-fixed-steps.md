# บันทึกการตัดสินใจ: ขั้นกวนผสม/ตกตะกอนมาตรฐานและค่าที่ไม่บังคับกรอก

วันที่จัดทำ: 2026-09-30

ประเภท: คำยืนยันโดยตรงของเจ้าของโครงการและข้อกำหนด TO-BE สำหรับ Jar Test

## เป้าหมายและแหล่งข้อมูล

กำหนดใน UMW2 ว่าหน้าต่าง “เงื่อนไขในการกวนผสมและการตกตะกอน” จะแสดงชุดขั้นใด และจะจัดการช่องที่ยังไม่มีค่ากรอกอย่างไร.

แหล่งข้อมูล: คำยืนยันของเจ้าของโครงการวันที่ 30 กันยายน 2569 และภาพหน้าจอ MAMIs ที่แนบในบทสนทนา.

## คำยืนยันของเจ้าของโครงการ

- มี 5 ขั้นมาตรฐานตายตัวและใช้เหมือนกันทุก Site.
- ตัวเลข `0` ที่แสดงในช่องเป็นเพียง placeholder แทนข้อมูลที่ยังไม่กรอก ไม่ใช่ข้อมูลจริง.
- ค่าสภาวะสามารถเว้นว่างได้; เมื่อแสดงข้อมูลที่ไม่มี ให้แสดง “ไม่ได้ระบุ”.

## ขั้นมาตรฐานจากหน้าจออ้างอิง

1. PRE-OXIDATION
2. COAGULATION
3. FLOCCULATION S1
4. FLOCCULATION S2
5. SEDIMENTATION

ภาพหน้าจอระบุหน่วยระยะเวลาเป็นวินาที และแสดงช่อง RPM ใน 4 ขั้นแรก แต่ไม่มีช่อง RPM ใน SEDIMENTATION. นี่เป็นข้อสังเกตจากภาพอ้างอิงที่แนบ.

## ผลต่อข้อกำหนด UMW2

- เพิ่ม JT-SET-032 ให้ทุก Site ใช้ชุดขั้นและลำดับเดียวกัน; ไม่ต้องมีการตั้งค่าหรือ mapping ขั้นตอนราย Site.
- เก็บเงื่อนไขเป็นข้อมูลต่อรอบใน `jar_test_mixing_conditions`; ระยะเวลาและ RPM เป็น optional. ค่าที่ยังไม่กรอกแทนด้วย missing/`NULL` ในข้อมูล ไม่ใช่ค่าศูนย์; แสดง “ไม่ได้ระบุ” ในมุมมองผล.
- การเว้นค่าสภาวะไม่ขัดขวางการบันทึกผลหรือเพิ่มรอบ และไม่ใช้คำนวณ dose หรือผลผ่าน/ไม่ผ่าน.
- ไม่มีการเปลี่ยน physical schema/DDL ในการตัดสินใจครั้งนี้; วิธีแทน stage code ทางกายภาพยังออกแบบภายหลังได้.
- ไม่แก้ legacy baseline; ภาพ MAMIs เป็นหลักฐานหน้าจออ้างอิง ส่วนข้อกำหนด UMW2 เป็น TO-BE.

## ข้อเสนอของ AI และประเด็นที่ยังไม่ยืนยัน

- ข้อเสนอ: ช่อง numeric ที่ยังไม่แตะควรรักษาสถานะค่าว่างไว้ แม้ UI จะวาด `0` เป็น placeholder เพื่อไม่ให้สับสนกับค่าที่ผู้ใช้กรอกจริง.
- ยังไม่ยืนยันว่าหากผู้ใช้พิมพ์เลข `0` ลงในช่องโดยเจตนา จะถือเป็นค่าจริงที่ยอมรับได้หรือไม่; คำยืนยันครอบคลุมเฉพาะ `0` ที่เป็น placeholder ของช่องว่าง.
- วิธีจัดเก็บ stage code ใน physical schema ยังไม่ได้ตัดสิน.
