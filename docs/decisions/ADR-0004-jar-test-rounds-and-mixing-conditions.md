# ADR-0004: Jar Test rounds and mixing conditions

- Status: Accepted; amended 2026-09-30 and 2026-10-01
- Date: 2026-09-25; amended 2026-09-30 (sequential rounds; optional values) and 2026-10-01 (Global default, Site override, optional S3, and physical setting schema)
- Scope: Jar Test transaction model in UMW2

## Context

UMW เดิมมีการทดลองเป็นรอบ โดยแต่ละรอบมี Jar 1–6 ส่วนร่าง Transaction ก่อนหน้านี้ให้บีกเกอร์อ้างงานตรง จึงแยกรอบหลายรอบไม่ได้ เจ้าของโครงการยืนยันภายหลังให้มี Global default สำหรับเงื่อนไขกวน/ตกตะกอน และให้ปรับ override แยก Site ได้; Site ที่ต้องใช้ FLOCCULATION S3 ต้องเปิดขั้นเสริมนี้ได้

## Decision

1. หนึ่งงาน `jar_tests` มีหลาย `jar_test_rounds`; `round_no` ไม่ซ้ำภายในงาน
2. `jar_test_beakers` อ้างรอบ และ `beaker_no` อยู่ในช่วง 1–6 โดยไม่ซ้ำในรอบ ผู้ใช้เลือกจำนวน Jar ที่จะทดสอบได้ ไม่จำเป็นต้องใช้ครบ 6
3. มีชุดค่าเงื่อนไข Global เป็น default และให้ Site ปรับทับค่า/การเปิดใช้ขั้นตามความจำเป็น; ชุดมาตรฐานมี PRE-OXIDATION, COAGULATION, FLOCCULATION S1, FLOCCULATION S2 และ SEDIMENTATION ส่วน FLOCCULATION S3 เป็นขั้นเสริมที่เปิดใช้ได้ราย Site และมีช่องเวลา/RPM เช่นเดียวกับ S1/S2. ค่าตั้งที่ resolve สำหรับ Site เติมเป็นค่าเริ่มต้นในฟอร์มสร้างงาน Jar Test
4. `jar_test_mixing_conditions` อ้างรอบและเก็บค่าที่ใช้จริงของการทดลอง; มีแถวสำหรับ 5 ขั้นมาตรฐาน และ FLOCCULATION S3 เมื่อเปิดใช้. ระยะเวลาเป็นวินาที; RPM ใช้กับทุกขั้นกวน รวม S3 แต่ไม่ใช้กับ SEDIMENTATION
5. `jar_tests.site_raw_unit_id` อ้างรายการ `site_raw_units` ที่เปิดใช้งานและมี `site_id` ตรงกับงาน ระบบตรวจทั้งตอนเลือกและตอนบันทึก
6. ผลคุณภาพน้ำวัดในวันเดียวกับวันทดสอบที่ระบุโดย `jar_tests.test_datetime`; ไม่เพิ่มฟิลด์วัน/เวลาวัดแยกหรือ `operating_status_id` ข้อนี้ไม่อ้างว่าเวลาของทุกการวัดตรงกับเวลาเริ่มทดสอบ
7. สภาวะกวนและตกตะกอนที่บันทึกในรอบเป็นข้อมูลการทดลอง ไม่ใช้คำนวณ dose หรือผ่าน/ไม่ผ่านในขอบเขตปัจจุบัน
8. งานใหม่เริ่มต้นด้วยหนึ่งรอบ ผู้ใช้เพิ่มรอบได้
9. ผู้ใช้กดเข้า Jar ที่เลือกเพื่อกรอกผล ก่อน submit ต้องมีผลครบทุก Jar ที่เลือกในทุกรอบ; Jar ที่ไม่ได้เลือกไม่ถูกนำมาตรวจความครบถ้วน
10. การแนะนำ Jar ที่ดีที่สุดเป็นระดับงาน โดยนำ Jar ที่ผ่านเกณฑ์จากทุกรอบมาเปรียบเทียบร่วมกันและแนะนำ Jar ที่มีต้นทุนสารเคมีรวมต่ำสุด; dose สรุปสุดท้ายยังแยกเก็บและอาจต่างจาก dose ของ Jar ที่แนะนำ
11. รอบใหม่เป็นการทดลองต่อจากรอบก่อน ผู้ใช้เริ่มรอบถัดไปเมื่อต้องการโดยกด “เพิ่มรอบ”; ระบบไม่สร้างหลายรอบรอไว้ล่วงหน้า
12. ผู้ใช้เพิ่มรอบถัดไปได้เมื่อผลคุณภาพของ Jar ทุกใบที่เลือกในรอบก่อนหน้าครบตามพารามิเตอร์ผลทดสอบที่ active; Jar ที่ไม่ได้เลือกไม่นับว่าขาดผล
13. ค่าระยะเวลา/RPM เป็น optional: ช่องที่ยังไม่กรอกอาจแสดง `0` เป็น placeholder แต่ไม่ถือเป็นค่าข้อมูลและต้องบันทึกเป็น `NULL`; เมื่อแสดงค่าที่ไม่มีให้แสดง “ไม่ได้ระบุ”. การเว้นค่าสภาวะไม่ขัดขวางการบันทึกผลหรือเพิ่มรอบ
14. เมื่อเพิ่มรอบใหม่ ระบบคัดลอกค่าที่บันทึกจริงใน `jar_test_mixing_conditions` ของรอบก่อนหน้ามาเป็นค่าเริ่มต้นของรอบใหม่ ไม่โหลด Global/Site Setting ใหม่กลางงาน; การแก้ค่าในรอบใหม่ไม่เปลี่ยนรอบก่อนหน้า
15. `jar_test_mixing_defaults` เก็บ Global default 6 แถวคงที่ และสร้าง `site_jar_test_mixing_settings` 6 แถวสำหรับทุก Site โดยคัดลอกจาก Global เมื่อสร้าง Site. Site แก้ค่าในแถวของตนได้และไม่รับผลจากการแก้ Global ภายหลัง. ใช้ `stage_code` คงที่และ `UNIQUE(site_id, stage_code)`; 5 ขั้นมาตรฐานเปิดเสมอ ส่วน FLOCCULATION_S3 เปิด/ปิดได้ราย Site

## Consequences

- ผลน้ำดิบยังอยู่ระดับงาน ส่วน dose และผลคุณภาพอยู่ใต้บีกเกอร์ของแต่ละรอบ
- UI ต้องแยกสถานะ Jar ที่เลือก/ยังกรอกไม่ครบ/กรอกครบ เพื่อป้องกัน submit งานที่ผลไม่ครบ
- บีกเกอร์ที่แนะนำ/เลือกสรุปผลต้องย้อนผ่านรอบไปยังงานเดียวกัน; หากมี Jar ผ่านหลายรอบ ให้เปรียบเทียบต้นทุนรวมข้ามรอบก่อนแนะนำ
- การสร้างรอบถัดไปเป็นการกระทำตามต้องการของผู้ใช้ ไม่ใช่การสร้างรอบเปล่าหลายรอบตั้งแต่เริ่มงาน
- UI ต้องไม่อนุญาตให้เพิ่มรอบถัดไปจนกว่าผลของ Jar ที่เลือกในรอบก่อนหน้าจะครบ
- UI ของ “เพิ่มรอบ” ต้องแสดงเงื่อนไขที่คัดลอกจากรอบก่อนหน้า และอนุญาตให้แก้เฉพาะรอบใหม่
- UI ไม่ให้เพิ่ม/ลบ/เปลี่ยนชื่อขั้น; แสดง 5 ขั้นมาตรฐานเสมอ และแสดง S3 เมื่อ Site เปิดใช้
- กติกาตัดสินเมื่อ Jar ที่ผ่านมีต้นทุนต่ำสุดเท่ากันยังไม่ได้กำหนด
- ค่า Global/Site ใช้เป็นค่าเริ่มต้นของฟอร์มสร้างงาน Jar Test; การบันทึก actual values ในรอบแยกจาก configuration. การแก้ค่าที่เติมไว้ในฟอร์มสร้างงานและการเก็บ snapshot ของรอบแรกยังเป็น Open Decision
- ค่าสภาวะที่ไม่มีเป็น `NULL` ไม่ใช่ตัวเลขศูนย์ และไม่เป็นเงื่อนไขบังคับของงาน
- การเลือกสารหนึ่งรายการต่อประเภทได้ข้อสรุปแล้วว่าล็อกระดับงาน ดู [ADR-0005](ADR-0005-jar-test-chemical-selection-per-job.md)
- เอกสารนี้กำหนดแบบร่างเชิงโดเมน; physical PostgreSQL DDL ยังต้องออกแบบและทบทวนต่างหาก

## Evidence

- คำยืนยันของเจ้าของโครงการวันที่ 25 กันยายน 2569
- คำยืนยันของเจ้าของโครงการวันที่ 30 กันยายน 2569 เรื่องการเปรียบเทียบ Jar ที่ผ่านข้ามทุกรอบและการเพิ่มรอบตามต้องการ
- คำยืนยันของเจ้าของโครงการวันที่ 30 กันยายน 2569 ให้กรอกผล Jar ที่เลือกในรอบก่อนหน้าให้ครบก่อนเพิ่มรอบถัดไป
- คำยืนยันของเจ้าของโครงการวันที่ 30 กันยายน 2569 ว่า 5 ขั้นเป็นค่ามาตรฐาน, `0` เป็น placeholder แทนค่าว่าง, สามารถไม่กรอกได้ และค่าที่ไม่มีให้แสดง “ไม่ได้ระบุ”; ภาพหน้าจอ MAMIs แสดงชื่อ/ลำดับขั้นและ RPM ใน 4 ขั้นกวนแรก
- คำยืนยันล่าสุดของเจ้าของโครงการวันที่ 1 ตุลาคม 2569: มี Global default, ตั้งค่า override แยก Site ได้ และ Site ที่ต้องการ FLOCCULATION S3 สามารถเปิดขั้น S3 ได้; ใช้ค่านั้นเป็นค่าเริ่มต้นใน job form
- [Legacy Jar Test baseline](../../JarTest/legacy-jar-test-product-functional-spec-th.md) หัวข้อ 11 และ 14
